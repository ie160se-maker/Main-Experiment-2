## 第1期からの変更点
1. **閲覧条件**：「質問へ進む」は、5枚すべての画像に到達すると押せる（秒数の下限なし。委託先の条件）。
   - 刺激画面の「十分に読まないと次に進めない仕様になっています」を削除し、「5枚すべての画像を表示すると『質問へ進む』ボタンが押せるようになります。すべての画像とキャプションを読み終えてから、ボタンを押してください」に変更。教示画面の操作方法も同じ趣旨に変更。
   - 閲覧時間（各スライド・4枚目・合計）の記録は第1期と同じ。
2. **自由記述の帰属**：30秒・空欄不可のまま（第1期と同じ）。
3. **スクリーニング**：年齢・Instagram の頻度に加えて「以前に、この調査（金沢大学の卒業研究「SNS広告に関する調査」）に回答したことがありますか」（はい／いいえ）を追加。
   - 対象外（18〜29歳以外、月2〜3回未満、回答歴「はい」）の人は、ダミー質問4問のあと確認コード（screenout）を表示。
   - 対象外の人は DataPipe のカウンタを使わず、データも保存しない。同じブラウザで開き直すとコードだけを再表示する。
4. **確認コード**：最後まで回答した人には main のコードを表示。事後説明で「回答の使用に同意しない」を選んだ人にも同じコードを表示する（謝礼に影響させない）。完了後に開き直した場合もコードを再表示する。
5. **同意文**：募集元を通じた募集であること、謝礼は募集元の規定によること、最初の回答によって質問が異なる場合があること、募集元のユーザーIDなどは収集しないこと、中断時の謝礼は募集元の規定によること、使用に同意しなくてもコードが表示され謝礼に影響しないこと、を追記。
6. **データ**：
   - 参加者IDの頭文字は `w-`（第1期は `m-`）。
   - CSV の末尾に `phase`（= 2）、`prior_part`、`viewed_all` を追加（106列）。最初の103列は第1期と同じ順。
   - 進行記録（ckpt0〜3）に `phase` を追加。

3. assignment_p2.js の `EXPERIMENT_ID`（'REPLACE_WITH_PHASE2_EXPERIMENT_ID'）を新しい実験IDに差し替える。

   - 委託先がコードを1種類しか使わない場合は、両方に同じ文字列を入れる。
   - 1人ずつ異なるコードが必要な場合は `CODE_WITH_ID = true`（コードの末尾に参加者IDの末尾4文字が付く）。
5. 本番URLで1〜2回動作確認し、その participant_id を記録して分析から除外する（DataPipe のカウンタは戻せない）。

## テストモード
- `index.html?test=1&cell=0`〜`5`：本番カウンタも本番保存も使わずに最後まで回答できる。完了画面に「保存されるはずのデータ」が表示される。
- スクリーニングで対象外の値（例：年齢35）を入れると、ダミー質問と screenout のコードを確認できる。
- `?multi=1`：同一端末から何度でも本番に回答できる確認用（ID は `multi-`、分析から除外）。参加者には配らない。

## 解析側の扱い（2026-11-16 決定）
- 第1期と第2期を合算して、事前登録どおりの主分析を行う（第1期の CSV には `phase` = 1 を付ける）。
- 主分析からの除外に「4枚目に到達していない」を追加（`slide4_first_arrival` が空）。第2期は5枚すべてへの到達が条件なので、最後まで回答した人は全員到達している。
- 追加の感度分析：4枚目の閲覧が5秒未満（`dwell_s4` < 5000）の人を除外／時期（phase）を要因に加える／第2期だけで分析する。
- `forced_pass` の意味は時期で異なる（第1期：各2秒・4枚目5秒、第2期：5枚到達のみ）。閲覧の比較には `dwell_s1`〜`dwell_s5` と `viewed_all` を使う。
- 所要時間による除外（中央値の1/3未満）は事前登録どおり全体の中央値で判定する。時期ごとの中央値も記述統計として報告する。

## 動作確認の結果（2026-11-16、ヘッドレスブラウザ、iPhone 13 相当）
